## 来源与问题
SRC-ATTENTION-001：用户要求推进“事情四象限、持续关注、统一周期重新评估”。SRC-ATTENTION-002：用户明确选择“每周一次，应用内提醒”，包含所有未完成且未取消的事情进入评估清单。

事情的重要性和紧急性会变化；长期事项容易因不紧急被忽视。需要手动分类及定期复核，避免把事件完成率误当优先级。

## 范围与规则
1. 仅针对事情。重要/不重要与紧急/不紧急组成四象限；首次未判断显示“未评估”，不默认第四象限。用户保存明确选择后生效。
2. 首版不提供持续关注标签、开关或筛选；优先级调整不触发事件催办。
3. 保留目标—模块—事情—事件原页面，在每个事情标题旁直接展示优先级及待评估标记；点击标签在右侧抽屉修改。不得新增四象限看板或独立关注页面。筛选仅作用于当前事情列表，不改变原有归属和排序。
4. 每周一次，仅应用内提醒；所有未完成、未取消且未删除的事情纳入。完成或取消的事情退出当前清单，原分类记录保留。

## 建议细则（本轮设计选择，待评审）
- 以 Asia/Shanghai 周一零点至下周一零点为一周。应用打开时显示本周待评估数，不要求用户在线接收定时推送。
- 每件事情逐项确认本周已评估，可以保持原分类；仅保存优先级调整不代表完成评估。未评估事情必须选择分类才可确认。
- 全部确认后本周提醒消失；下一周重新纳入有效事情。跨过多周只显示当前周，不堆积旧提醒。
- 本周新增或重开的事情立即纳入；完成/取消后同周重开也需重新确认。调整分类与“确认本周评估”可一次保存。
- 换绑不清空分类或本周评估记录；不提供一键将所有事情标为已评估。

## 异常与边界
读取失败不展示虚假零待办；保存失败保留输入，不提示成功。写入需检查账号权限、事情归属和最新状态；发生并发修改、删除、完成或取消时拒绝过期提交并提示刷新。成功后读回，重复确认不得新增重复评估记录。跨周提交以保存时当前周期为准并提示周期变化，重新核对后确认。

## 验收条件
| ID | 可观察结果 |
|---|---|
| AC-01 | 未判断事情显示未评估标签；选择四类任一项后读回一致。 |
| AC-02 | 事情列表及抽屉仅提供优先级与评估操作，不出现持续关注入口。 |
| AC-03 | 全账号有效事情纳入每周评估；在原有目标/模块上下文展示每件事情的待评估标记，不新增独立清单页面。 |
| AC-04 | 保持分类并确认后待评估数减一；仅保存优先级调整不减少。 |
| AC-05 | 新周重新评估；离线多周不叠加提醒；完成或取消不计入。 |
| AC-06 | 新增、重开、换绑及跨周提交符合建议细则。 |
| AC-07 | 越权、并发、重复确认、写入失败及读回失败不造成虚假成功。 |
| AC-08 | 空清单、筛选无结果、错误反馈和手机布局清晰可用。 |

## 不做
AI 自动分配象限、事件级四象限、每件事情独立周期、飞书/邮件/系统推送、自动创建行动、修改事件状态、完整全局工作台、多人共享评估。
