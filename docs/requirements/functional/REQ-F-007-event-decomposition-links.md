## 问题、场景与价值

一个事件过大时，用户需要拆成可执行的小事件，分别跟进责任人、日期和状态。行动完成后若仍需回访或等待后续结果，可建立独立跟进事件并关联历史事件，保留原完成事实。

价值：明确下一步行动，区分任务分解与后续跟进，防止进度统计对父事件及子事件重复计数。

## 建议范围

1. 在同一事情内，将事件拆成子事件，允许继续细分；每个子事件只有一个父事件，禁止自身引用和循环。
2. 子事件沿用事件名称、说明、责任人、计划日期和四状态。日期只到天；责任人和日期不自动猜测。
3. 父事件仍由用户手动完成，子事件状态变化不自动修改父事件或其他层级状态。
4. 同事情内建立独立事件的关联，区分“跟进”与一般相关；关联不改变归属、不形成父子关系、不传播完成状态。移除关联不删除事件。
5. 后续跟进可以关联已完成事件；创建跟进不会撤销历史事件完成。
6. 写入前校验权限、归属及当前状态，成功后读回。重复提交不重复创建，冲突提示刷新，结果未知时允许核对，不静默重试。

## 完成约束建议（待确认）

- 父事件完成前，所有未取消的后代事件均需完成。已取消子事件不阻塞，单独展示取消数量。
- 子事件全完成后，父事件仍待手动完成；提示“子事件已完成，父事件待确认”。
- 已完成父事件下新增子事件或重开子事件时，先提示需要用户显式重开相关已完成祖先，不静默撤销完成。
- 取消父事件不默默批量取消子事件；本片建议有未结束子事件时阻止取消，提示逐项处理。
- 所有子事件都取消时不自动完成父事件，用户需明确选择完成或取消；如何允许手动完成待确认。

## 完成率建议及与 REQ-F-005 的关系

采用“未取消的叶子事件”计数。叶子事件指没有子事件的事件，包含从未拆分的独立事件；结构上有子事件的父事件不计数。递归拆分时只计最末级，关联关系不增加计数。

事情的事件完成率 = 已完成有效叶子事件数 / 有效叶子事件总数 × 100%。沿用整数百分比与准确计数，无有效叶子时显示“暂无进度”。未确认候选不计入。

例：A 拆为 A1、A2，另有未拆分 B；A1 与 B 完成、A2 进行中，则为 2/3，显示 67%，A 不重复计数。

父事件可展示其后代叶子完成计数，但 100% 不代表父事件已经完成，必须同时显示父事件自身状态。这是行动数量比例，不是工作量或目标达成率；继续拆分可改变分母并使百分比下降。

结构性父事件的子项全部取消时，该分支没有有效叶子，不把父事件自动补回分母。取消父事件与未结束后代的约束须与上述规则一起确认。

REQ-F-005 当前口径不包含父子拆分。此处属于待审变更，不覆盖现行开发版；确认后同步修改 REQ-F-005 及其原型、技术、测试，再实施。

## 验收条件草案

| 编号 | 可观察结果 |
|---|---|
| AC-01 | 同事情内创建子事件并再次细分，重新打开后层级、责任人、日期和状态正确。 |
| AC-02 | 子事件全部完成后父事件状态保持不变，由用户手动完成。 |
| AC-03 | 若采用完成约束，未取消后代尚未完成时拒绝完成父事件，提示具体阻塞事件；无部分状态变更。 |
| AC-04 | A1、A2、B 示例显示 67%，完成 2/有效 3，不重复统计父事件；多级拆分只统计最末级。 |
| AC-05 | 全部有效叶子完成显示 100%，但未完成父事件仍明确标识待确认；全部取消显示暂无进度。 |
| AC-06 | 跟进关联已完成事件后，历史状态保持完成；移除关联后两事件均保留。 |
| AC-07 | 自身、父子循环、跨事情、越权或失效对象的拆分或关联请求被拒绝；不回退到其他归属。 |
| AC-08 | 重复提交、并发状态变化、保存失败及读回失败不造成重复事件或虚假成功。 |
| AC-09 | 已完成父事件下新增或重开子事件，不静默修改父事件状态；取消路径按已确认约束执行。 |
| AC-10 | 事情整体换绑后，其事件树及内部关联完整保留，统计结果不因位置变化而重复计数。 |
