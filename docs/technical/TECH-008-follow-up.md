# TECH-008 事件私聊催办

**类型**：技术方案
**状态**：approved
**负责人**：待指定
**更新时间**：2026-11-13
**source_requirements**：REQ-F-004
**source_technical**：TECH-002、TECH-003、TECH-006
**关联文档**：PRO-003、TEST-005

事件行铃铛数字来自服务端已发送并读回确认计数。规则默认不存在/关闭，用户核对事件责任人及唯一 open_id、消息内容、北京时间、每日一次及次数上限后开启。暂采用人工身份核实，不宣称姓名搜索已实现。事件版本变化、完成、取消时停用，不把 AI 建议当授权。

follow_rules 保存规则、版本、授权事件版本和下次时间，follow_attempts 保存每轮操作标识及 pending/confirmed/unknown。到期原子领取并先写 pending；外部调用采用 bot 身份、固定消息命令、唯一幂等键，成功后读回同消息标识和正文。失败或超时标 unknown 并停用，启动发现未完成 pending 只暂停不重发。次数达到上限停用，关闭期间不补发；这是安全优先的至多一次尝试，不承诺每条都送达。

普通测试使用 fake sender，不发送真实消息。本地进程关闭时不调度；正式托管、多人权限与高可用不在本片。真实责任人送达仅在用户明确开启该规则后执行。

发送窗口说明：暂停仅阻止后续轮次，已领取并向飞书提交的在途消息无法保证撤回。确认读回计数即使遇到并发暂停仍入账，但不重新开启规则。
