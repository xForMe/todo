## 问题与价值

用户希望对已确认的待办持续跟进，通过飞书向责任人私聊催办，减少重复人工提醒。私聊目的地已由用户明确；单次连通性测试授权不等于正式自动催办授权。

## 建议规则（待评审确认）

- 默认关闭。用户为具体事件核对责任人的唯一身份、发送身份、消息模板、触发日期、时区、发送时间、间隔及次数上限，明确确认后开启。
- 不能仅凭姓名匹配并发送；重名、不明确或无可用身份时禁止开启。
- 建议以应用身份发送，事件到期后的次日北京时间 09:00 首次催办，每日最多一次、累计最多三次，达到上限暂停。上述数值与是否排除非工作日均未获用户确认。
- 缺少截止日期不能开启本规则。日期只有天粒度时不自行虚构具体截止时刻。
- 发送前复查授权仍有效、责任人未变、事件未完成/取消且本轮未发送；完成、取消、关闭催办后停止后续发送。
- 责任人、截止日期、发送身份或模板变化后暂停，重新确认授权再恢复。错过发送窗口不补发一串历史催办。
- 消息只包含用户批准的事件信息和模板字段，不擅自附带整段聊天或文档。AI 草稿须确认后才能成为模板。
- 展示发送记录、实际内容和结果；区分已提交、读回确认、结果未知和明确失败，不把成功发送当成收件人已读。
- 失败或结果未知不静默重试，先查询核对；仍无法确认时暂停并交用户处理。重启及重复触发不得重复发送同一轮。

## 验收条件

| 编号 | 可观察结果 |
|---|---|
| AC-01 | 未明确开启或身份未确认时，任何识别结果与到期条件均不产生消息。 |
| AC-02 | 到达已批准条件后只向指定责任人私聊发送批准内容，并可查询记录。 |
| AC-03 | 同轮重复触发或重启不重复发送；结果未知时不自动重发。 |
| AC-04 | 完成、取消、撤销授权及责任人变更后停止后续催办；已发送记录保留。 |
| AC-05 | 超过次数上限、权限不足及收件人不可达时暂停并提示原因。 |

## 不做

不群发、不群内催办、不电话或短信加急、不自动升级给上级、不因收到回复自动完成事件、不承诺应用未运行时仍能发送。后台运行与调度部署作为后续技术方案边界明确。
