## 来源、场景与价值
SRC-WORKBENCH-001：用户启动完整全局工作台与持续关注。SRC-WORKBENCH-002：用户明确选择“新增全局首页，保留现有工作页”。

用户打开应用后先了解跨目标的待执行行动、待跟进、关注事情和本周待评估，再进入既有页面推进。完整指覆盖产品规划中的目标概览、执行、关注、评估四类视图，不代表扩大外部接入或增加目标达成率模型。

## 范围与建议规则
1. 新增全局首页作为默认入口；保留原“目标与事情”工作页。从首页跳转携带目标/模块/事情及事件定位，返回首页保留本次筛选。
2. 只汇总当前账号未删除记录。全目标为默认范围，可按目标筛选；所有卡片、计数、列表使用同一范围，明确显示当前范围。
3. 目标概览列出目标、模块数、事情数和已完成事情数。每件事情可展示 REQ-F-005 的叶子事件完成率及准确计数；不平均百分比、不生成跨目标总进度、不把行动数量比例称为目标达成率。
4. 执行列表提供全部未结束、已逾期、今日到期、进行中、待跟进、未排期筛选。按北京时间日期判断：截止日期早于今天且未完成/未取消才逾期；今天截止不算逾期；无截止日期归未排期。有未结束后代的父事件也可显示，明确标为父事件，不能误当重复行动数量。
5. 待跟进仅指已有明确“跟进”关系且未完成/未取消的后续事件，不从标题或 AI 推测。列表按事件身份去重；一个事件可同时属于逾期和跟进，各筛选数量不可相加当总数。
6. 排序建议为有截止日期的按日期升序，再按名称和稳定标识；无日期置后。每行显示完整归属、状态、日期，点击打开右侧详情，可定位原工作页。首页不新增一键完成或批量写入。
7. 持续关注使用 REQ-F-009 的规则；默认显示活跃关注，可查看已结束并取消关注。
8. 本周评估复用 REQ-F-008 的范围与北京时间周一换周规则。显示未完成且未取消的待评估事情及数量，点击定位原工作页评估，不把浏览或关注当作评估完成。
9. 刷新读取现有业务状态，不触发飞书读取、AI 调用或催办。展示读取状态；返回首页重新读取，失败保留上次内容时明确标为旧数据。

## 异常路径
全空、筛选无结果、部分区块失败、全局读取失败分别展示。失败区块不显示虚假零值；数据已删除或换绑时提示刷新并使用最新归属，不打开错误事情。跳转及关注修改仍检查权限，失败不静默切到其他对象。大列表不得静默截断，正式方案须采用分页或分批加载并显示总数与已加载数。

|---|---|
| AC-01 | 首次打开进入全局首页，原工作页仍可用；跨目标跳转定位正确并可返回。 |

| AC-05 | 关注切换与原工作页同步，本周评估不因浏览或关注自动完成。 |
| AC-06 | 无事件显示暂无进度，不展示未经定义的目标达成百分比。 |
| AC-07 | 空态、部分失败、过期数据、失效跳转和分页均有明确反馈。 |
| AC-08 | 手机、长路径及键盘使用可操作，详情统一右侧抽屉。 |
