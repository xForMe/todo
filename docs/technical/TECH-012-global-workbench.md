用户要求按 PRO-008 开发，采用其默认首页、关注生命周期、日期筛选和排序。先关注写入切片，再只读汇总。复用 SQLAlchemy、FastAPI 和原生前端，无新增依赖。

迁移 0009 增加 thing_attention（item_id 主键、enabled），旧数据默认未关注；完成/取消、重开和换绑保留标记，删除通过可见性过滤。写入 POST /api/items/{id}/attention，验证账号、事情类型、状态枚举、版本与 operation_id；已结束事情仍允许取消或开启关注。BEGIN IMMEDIATE 与既有版本比较更新保持 SQLite 并发边界。与 work_operations 同事务，读回失败保留原操作 ID，使用 /api/operations/{id} 核对，不自动重试。

GET /api/workbench 在一次数据库读事务中返回账号内未删除工作、关注、优先级与评估、事件树和关联；显式北京时间日期。SQLite 显式 BEGIN 保证多个 SELECT 同快照。无外部请求，不触发模型或发送。前端复用数据生成筛选/计数，按每页20条展示行动、关注与评估，显示总数和页码；此版本快照仍全量读取，超大数据量成本尚未做性能承诺。

前端新增 workbench.js / workbench.css，工作台为默认首页，原工作页保留。原事情卡片旁增加关注入口与仅关注筛选，与每周待评估筛选取交集。导航重新读取快照，失败整体显示不可用，不把错误伪装零结果。请求序号防止旧返回覆盖新状态；关注写入与未知回执期间禁止第二次关注修改。前端输入均转义，关注点击不冒泡至编辑。

全局详情统一右抽屉；跳转前读取最新快照，验证完整父链，失效对象提示刷新，不回退其他事情。优先级评估继续使用原抽屉；首页不增加一键完成。跟进取 event_links 的 source（新跟进事件；target 为历史事件）（kind=followup），父事件标识取 event_children.parent_id，事情进度仅有效叶子。排序使用日期、名称、ID，无日期最后。

生产 PostgreSQL、分页数据库查询优化不在本次验证；SQLite 升级前停止服务、备份，核对所有原业务表摘要。测试用隔离数据库、关闭来源 Worker，不修改真实事情进行演示。普通启动继续不迁移。
