# TECH-011 事情优先级与每周评估

**类型**：技术方案
**状态**：approved
**负责人**：待指定
**更新时间**：2026-11-14
**source_requirements**：REQ-F-008；SRC-ATTENTION-005 用户按当前原型授权开发
**关联文档**：PRO-007、TEST-008、TECH-002、TECH-003

新增独立 thing_priorities 表，按事情 ID 保存优先级（0 未评估，1—4 四类）与最后评估周。复用工作记录版本、账号过滤、操作回执和 SQLite 写事务。迁移 0008 仅建表，不改写旧记录。不新增依赖；固定 UTC+8 业务时区采用标准库。

GET /api/priorities 返回服务端当前周、账号有效事情的分类与待评估标记。POST /api/items/{id}/priority 接收 expected_version、week、priority、review、operation_id；检查身份、事情类型、有效状态、版本与周期。优先级非零才可确认评估。每次成功新操作增加工作版本；同操作重复返回已保存结果。复用 /api/operations/{id} 核对不确定结果，再读取优先级。事务失败全部回滚，读回失败报告待核对。

事情从结束状态重开时清空评估周；换绑保留评估。北京时间每周一零点换周，浏览器回到前台及每分钟刷新读取，后台不发消息。跨周提交拒绝并刷新后核对。前端标签直接附在事情卡片，右抽屉操作；加载失败显示错误，不冒充零待评估。优先级标签为内容状态，保留文字，其他操作沿用图标规范。

升级先停止本地服务并备份，核对既有表摘要。只验证 SQLite 本机版本，PostgreSQL/生产不包含本次交付。
