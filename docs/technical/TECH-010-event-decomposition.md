SRC-EVENT-004：用户要求开始开发，按 PRO-005 当前完成规则实施。SQLite 开发环境，复用 SQLAlchemy/Pydantic/模型 HTTPS 适配器，不增加依赖。

work_items.parent 保持事情归属。event_children 独立保存单父关系；只能新建子事件，不能重挂已有事件，因此不产生环。event_links 保存同事情的相关/跟进关系，移除不删除事件。事情整体换绑时事件 ID 不变，结构与关联保留。迁移 0007 只新增表及约束，不改写旧记录。

GET /api/events/{id}/structure 返回同事情结构、关联和内容快照。POST /api/events/{id}/children 接收用户选定的 1—20 条事件字段及 snapshot/operation_id，事务校验权限、当前状态、快照、名称重复，原子创建，持久化回执后读回。相关写入使用 SQLite BEGIN IMMEDIATE；非 SQLite 暂拒绝该切片写入。GET /api/event-operations/{id} 核对不明结果；同键不同请求拒绝。链接同样快照确认与回执，删除后保留回执。

统一 work.write_item 增加后代完成约束与祖先重开约束，覆盖 UI 及 AI 来源更新路径。父事件完成/取消前未取消后代均须完成；已结束祖先先显式重开。所有子事件取消允许用户手动完成，前端明确标识统计暂无进度。叶子计数包含未拆分事件，父状态独立。

AI POST /api/events/{id}/decomposition 使用显式 consent，提交当前事件的标题/说明、已有子事件标题/状态及用户补充要求；无其他事情或飞书自动读取。复用 UAIAPI HTTPS 传输，无工具权限、超时与输出限制、不自动重试；结构化候选最多 10 条，不猜测责任人日期。生成结果不写事件表，确认时重新校验快照与实际状态。错误仅返回安全提示。

前端维持原页面与右抽屉。操作按钮统一 SVG、aria-label、悬停和聚焦提示；导航/事情/事件名称保留文字，催办保留次数。禁用及进行中状态可感知；手机表格内部滚动，页面不横溢。


实现补充：同一 children 端点接受 followup 操作，创建独立事件并原子保存跟进关系；允许跟进已完成历史。结构快照同时返回该事情内的事件字段，抽屉以服务端读回结果展示，避免旧页面内容配新快照。验证 TEST-007，当前待业务验收。

## 自动生成交互（2026-11-14）

SRC-EVENT-005：打开可拆分事件后自动调用建议接口，不再要求填写补充内容、勾选授权或点击首次生成。建议区置前，手动创建折叠为备用；补充要求在可选展开区。首次自动请求使用空 instructions，consent=true 来自用户当前明确授权，后端仍执行范围/快照检查。页面内按事件、快照、补充要求复用请求和结果；失败不静默重试，显式重新生成可替换缓存。生成不锁住关闭与手动创建，关闭/切换后的异步结果仅缓存，不更新其他抽屉。
