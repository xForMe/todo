## 可读性与类型

- 文件、函数、变量用 snake_case，类用 PascalCase，常量用 UPPER_SNAKE_CASE。领域事件使用 work_event 避免与框架事件混淆。
- 导入使用标准库、第三方、本项目分组，由 Ruff 排序；禁止星号导入和导入时副作用。
- 函数参数、返回值和公共数据结构写类型注解。运行时输入必须校验，类型注解不是权限或运行时安全机制。
- 不随意使用 Any、type: ignore、noqa；必要时限定具体规则并写原因。不用可变默认参数。
- 公共模块、类、函数写简短文档字符串；复杂接口说明参数、返回和异常。注释解释业务原因而非复述代码。

## 分层和数据边界

- router 只负责 HTTP 输入输出和身份依赖；service 负责业务规则和事务组织；repository 负责数据库访问；schemas 与持久化 models 分开。
- 前端只能调用接口。业务模块不直接执行 CLI、读取令牌或耦合供应商 SDK；由 integrations 提供适配。
- 不为简单逻辑创建通用框架、万能基类或无需求的抽象层。先使用标准库，再评估必要依赖。
- 写操作必须检查所有者、对象归属、当前状态及版本；创建使用操作标识保证幂等，事务失败不得留下部分写入。
- 写后读取实际结果；写入可能已提交而读回失败时报告“结果待核对”，禁止静默重试和伪报成功。
- 责任人名称不等于权限身份。日期时间是否带时区由接口契约明确，不使用隐含服务器时区处理业务时间。

## 异常、日志与异步

- 捕获可处理的具体异常，保留异常链；不得吞掉异常或把失败转换为空数据成功。
- 对外返回可理解的错误与请求标识，不泄露堆栈、凭据、原始命令输出和个人资料。
- async 路由中不得直接执行阻塞数据库或 subprocess 调用；按调用链选择同步路由、线程池或异步客户端。
- 客户端、文件、事务使用上下文管理，明确超时与关闭；不得在请求中执行不受控长任务。

## CLI 接入专门规则（未来实现时）

- 先验证 CLI 的名称、来源、版本、身份、授权范围与结构化输出；存在 CLI 不代表接口权限已获授权。
- 固定可信可执行文件，参数采用数组，shell=False；不拼接用户输入形成命令。子命令与选项使用显式白名单。
- 明确超时、输出大小上限、退出码、JSON 结构及错误分类；超时后处理进程退出，不只停止等待。
- 秘钥不作为命令行参数或日志内容；不得修改用户默认账号、登录态或全局配置来使测试通过。
- 外部写命令必须经人工确认、范围和状态检查；超时视为结果不确定，先核对，不自动重试。
- 单元测试使用 fake runner；真实 CLI 测试必须单独明确授权，默认检查不得访问飞书。

## 依赖与检查

- pyproject.toml 声明直接依赖，uv.lock 锁定解析结果；提交二者。不得提交 .venv、缓存或真实 .env。
- 引入前核对功能、维护、许可证、安全风险和运行成本；依赖升级不与无关业务修改混在一起。
- 从 code/backend 执行 uv sync --locked，再执行 uv run --locked python ../scripts/check.py。
- 统一检查包含 Ruff lint、格式检查、mypy strict 和 pytest；失败不能写成已验证。检查脚本不自动修复文件。
- 对有业务效果的修改测试成功、拒绝、冲突、重复、失败及读回不确定路径；不用纯镜像实现的测试替代行为验证。
- 本地检查、真实数据库、真实 CLI、生产验证分别报告，不相互替代。业务切片仍须完成原型确认。
