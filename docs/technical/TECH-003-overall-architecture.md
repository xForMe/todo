## 2. 系统边界与依赖方向

```text
浏览器前端（未来）
    │ HTTP / JSON，OpenAPI 契约
    ▼
FastAPI 路由：身份、输入校验、响应转换
    ▼
业务服务：权限范围、状态、幂等、事务、结果核对
    ├─ repository → 关系数据库（候选）
    └─ 适配接口 → 飞书 CLI / 大模型 / 决策模型（未来）

后台 Worker（未来有需求时） → 同一业务服务与适配接口
```

浏览器不得直连数据库或持有模型/飞书凭据。路由不直接调用 CLI。外部适配器不自行改变业务状态，结果先交由业务服务处理。前端与 Worker 均不能绕过业务规则。首期不拆微服务，不引入消息队列、向量数据库或多代理框架。

## 3. 业务模块与数据归属

- goals：目标；modules：目标下模块；matters：持续推进的事情；work_events：具体行动。
- 当前归属严格为目标→模块→事情→事件，服务端检查父项存在和数据所有者。
- 事情、事件的四状态及时间、责任人来自 REQ-F-001。责任人文本不作为权限主体。
- 未来拆分关系与事件关联关系分别建模；完成与关联保持独立，不因新增反馈自动撤销完成。
- materials、suggestions、priorities、reviews 等仅为后续候选模块，需求确认后才创建实现。
- 本系统业务记录与飞书原始资料分别保存来源信息；同步规则未确认前，不自动覆盖本地状态。

## 4. 接口与写入流程

前端使用 OpenAPI 作为接口契约；是否生成前端客户端随框架确定。输入与输出 schema 分开，不直接暴露 ORM 对象。鉴权在服务端执行，不能依赖前端隐藏按钮。

用户确认提交 → 校验输入和身份 → 检查对象范围、状态及版本 → 以操作标识判重 → 事务写入 → 查询核对 → 返回实际保存结果。

建议使用版本字段实现乐观并发控制；具体字段、错误码和事务边界在业务 TECH 中细化。重复创建不能仅按名称判重。事务成功但读回失败时返回可核对的操作标识，不显示成功，不自动重复提交。

## 5. CLI 与智能辅助边界

飞书 CLI 是外部访问适配方式，不是权限替代方案。上线前验证可信可执行文件、版本、非交互认证、账号范围、输出格式、分页、错误、限流和超时行为。尚不指定任何命令。

适配器使用明确参数列表和允许的子命令；不得执行模型生成的任意 shell 字符串。读取结果转换成内部结构，保留来源标识和采集时间，不把 stderr 或原始响应直接展示给用户。

模型建议与用户确认后的业务记录分开；建议包含依据、候选关联和不确定性。外部资料中的指令不是执行授权。模型不能直接创建任务、发送消息或调用写命令。CLI 外部写入必须走确认、幂等或结果核对策略，禁止静默重试。

长期任务和统一周期提醒在需求确定后再设计 Worker；进程内临时定时器不能宣称具备可靠调度。持久化任务、重复执行控制及恢复机制须单独设计。

## 7. 部署、测试与演进

脚手架仅按需在 127.0.0.1 运行。生产部署前必须明确身份机制、TLS、可信代理、CORS/CSRF、凭据注入、备份恢复和日志脱敏。单人使用也必须检查所有权。

按顺序推进：工程基础 → 原型确认及手动闭环技术设计 → 数据库与业务接口 → 前端联调 → 独立需求批准后的关联、评估、飞书读取和智能辅助。该顺序不构成工期承诺。

本地 lint、类型检查、进程内 HTTP 测试只证明工程基础。数据库事务与冲突需要真实测试数据库验证；CLI 需要独立授权的集成验证；业务闭环需要端到端验收。报告分别列出这些证据。
