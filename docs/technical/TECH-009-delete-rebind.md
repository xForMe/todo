新增 work_deletions 记录逻辑删除及幂等回执，不物理删除原记录或历史操作。活动工作查询排除已删除 ID。GET /api/items/{id}/deletion 返回确认快照及影响计数；POST 同路径携带 operation_id、snapshot、target_id；GET /api/deletions/{operation_id} 核对结果。
一次事务完成归属、来源、建议、提醒更新及删除记录。所有权、同类型、状态、快照校验前置。SQLite 事务使用 BEGIN IMMEDIATE 串行写入删除；数据库触发器阻止并发创建/更新引用已删除对象以及删除仍有活动下级的对象。模型提交再次核对工作范围快照，避免在途识别写回旧归属。当前 SQLite 为验证范围，其他数据库不宣称已支持此切片。
直接子项换父项且版本递增，所有后代身份不变。事情上的文档迁至接收事情；待确认建议更新归属和仍有效的事件版本，历史确认正文保留；全部受影响来源暂停并递增版本；受影响催办暂停，发送中的记录阻止操作。applying 建议阻止操作。失败回滚，响应不明使用持久回执核对，不静默重试。迁移 0006 只新增表与写入约束，先备份。

## 同名模块融合（2026-11-14）

SRC-DELETE-002：用户明确确认“同名模块合成一个，内容合在一起”。目标换绑时，对接收目标下与转入模块名称完全相同的模块合并，优先保留接收方模块身份；事情和事件追加保留，不按同名自动去重。不同模块名称不猜测合并。模块双方说明均保留，超出说明长度上限则拒绝并回滚。既有两条“智能输配”模块经本次授权合并。前端确认文案说明同名模块融合，仍沿用右侧抽屉。
